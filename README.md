# AI Workbench

> 一个链接，收进所有作品。首页是门面，点进去 —— **能跑的就真跑，跑不了的如实演示**。

**在线**：`https://liancang.app.workbuddy.host/`（口令 `tingcang-2026`）

---

## 为什么做成「工作台」

发布的沙箱**一次只允许一个在线应用**（实测：发布一个全新目录，也会复用当前活跃沙箱，把在线的那个顶掉）。
所以与其让作品互相顶，不如把**「工作台」本身**作为发布主体 —— 一个入口，挂住所有作品。

```
/            首页（作品卡 + 状态标注）
/link/*      链藏   —— 真跑（贴链接 → 抓取 → 结构化 → RAG 带出处问答）
/voice/*     听藏   —— 演示（看成品：纪要 / 点时间戳回听 / 原文 / 导出）
```

---

## 结构

```
app/
  hub.mjs       单端口总服务：子进程编排 + 反向代理 + 统一鉴权与限流
  index.html    工作台首页
  link/         ⚙️ 链藏（生成物，不进 git）
  voice/        ⚙️ 听藏（生成物，不进 git）
scripts/
  sync.mjs      从各仓库同步作品进来（顺带适配云端配置）
```

---

## 关键设计：不改子项目代码，用「子进程 + 反向代理」

| 做法 | 好处 |
|---|---|
| **子进程**起每个作品（各自端口，只监听 127.0.0.1） | 作品代码**零侵入** —— 各自仓库照常开发、本地照常跑 |
| **反向代理**按路径前缀分发（`/link/*`、`/voice/*`） | 以后加新作品 = 加一条规则 + 一个子进程 |
| **鉴权与限流只做在 hub 层** | 子应用收到 `VV_ACCESS_TOKEN=''`，不会把代理来的请求误判成未授权 |

**代价**：发布目录里会有两份作品副本。
解法：把 `app/link`、`app/voice` 明确定义为**生成物** —— 每次由 `sync.mjs` 从各自仓库**重新生成（整目录覆盖）**，
所以不会出现「改了一个仓库、发布用的却是另一个版本」的漂移。

唯一需要配合的约定：**作品前端里的 API 路径要写相对路径**（`api/xxx`，不是 `/api/xxx`），
否则挂在子路径下会请求到工作台根上。

## 同步与运行

```bash
node scripts/sync.mjs     # 从 D:/VibeCoding/{link-vault,voice-vault} 重新生成 app/link、app/voice
npm start                 # → http://localhost:3000
```

`sync.mjs` 还会把作品 `.env` 里**云端不适用的路径**自动改写：
注释掉 `VV_DATA_DIR`（云端改用项目内 `data/`）· `VV_PYTHON=python3` · 清空 `VV_MODEL_DIR`。

## 关于「演示模式」

云端沙箱里没有 Whisper 模型（1.5 GB），也不适合长时间 CPU 推理，
所以听藏在云端**只展示已生成好的成品** —— 能点开纪要、点时间戳回听、看转写原文、导出 Markdown，
但录音与上传需要在本机运行完整版。**界面如实标注，不假装能跑。**

## 访问口令

云端设了 `VV_ACCESS_TOKEN`，首次访问拼在链接后面即可，之后浏览器会记住：

```
https://liancang.app.workbuddy.host/?token=你的口令
```

> 为什么不用 HTTP Basic：云端网关会把 `Authorization` 头**剥掉**（本地正常、上云一律 401）。
> 所以改走 Cookie / `X-VV-Token` / 查询参数三条通道。

⚠️ `.env` 里**本地也保留了口令**（`hub_token`，不是子应用的 `vv_token`）——
这是有意的：发布打的是当前目录，漏设口令会把「会花 DeepSeek 钱的入口」裸奔出去。
本地要免登录就临时清空 `VV_ACCESS_TOKEN` 再启动。

## 演示数据从哪来（许可与可公开性）

听藏子页里那条 38 分钟的会议成品，音频取自公开语料 **AISHELL-4**
（AISHELL 开源中文会议语料，**Apache-2.0**）测试集 `S_R004S04C01` ——
8 通道远场、5 位说话人、**剧本式演练**（一场「家长会」讨论）。

**为什么用它**：真实会议（多说话人 / 插话 / 远场混响）· 许可可直接分发 ·
**内容可公开**（剧本演绎 + 说话人只标 `001-M`；逐条扫过 **0 手机号 / 0 身份证 / 0 邮箱 / 0 金额 / 0 机构名**）。
原素材为 8 通道阵列，**按实测选出的信噪比最优单通道**降为单声道 16 kHz（38.3 分钟压到 13.5 MB）。

> 细节（多通道对比数据、为什么混音最差、以及语料暴露出的「静音段幻觉」缺陷）见
> `voice-vault` 仓库 README §四。
